# W6.1/W6.2 — what STREAMING actually costs to implement, counted

Written 2026-08-24. **Static audit of committed code; zero compute cost.**
Closes the "currently absent" cost argument that `PLAN_B_REBUILD.md` W6 names as
what makes a modest benefit sufficient.

The plan states the cost argument as an assertion — "unused PAT slot 6, one PTE
bit, TLB carry, one fill-path predicate ... no new coherence states, no new
structures." Every clause of that is checkable against two trees that exist.
This is the check. **One clause is wrong, and in our favour.**

## Method

Two repositories, each diffed against its pre-STREAMING base:

- **`~/DutyFree-Gem5`**, base `ce48ff93bd` (parent of `5bdfcd8e19`, the first
  STREAMING commit) → HEAD `356e7b7d0e`.
- **`~/DutyFree/linux`**, base `e8f897f4af` (Linux 6.8) → HEAD `b9f60fafda`,
  16 commits.

Counting rules, fixed before looking: added lines only, blank lines and
comment-only lines excluded, `DPRINTF`/logging excluded, and in gem5 a line
counts as STREAMING-attributable only if it mentions `stream` case-insensitively.
That rule has one false positive, excluded by hand: the `SF_Eviction` event
declaration, whose description contains "up**stream** sharers." Scripts,
testcases, build configs, `tools/`, `Documentation/`, KUnit and selftests are
excluded from the implementation count and reported separately.

## The structural result

This is the claim that matters to an architecture reviewer, and it is a set of
zeros. Counted across the whole gem5 protocol diff, base → HEAD:

| SLICC construct | added | removed |
|---|---:|---:|
| coherence states (`State:`) | **0** | 0 |
| message types (`CHIRequestType:`) | **0** | 0 |
| structures (`structure(`) | **0** | 0 |
| enumerations | **0** | 0 |
| events (`Event:`) | 1 | 0 |
| transitions | 4 | 0 |
| actions | 2 | 0 |

**The one event, four transitions and two actions are not STREAMING.** They are
`SF_Eviction`, `Initiate_SF_Eviction` and `CheckSFFill` — the finite
snoop-filter *model*, which is baseline apparatus present in the write-back arm
too. Remove them and STREAMING adds **zero** of every SLICC construct.

What STREAMING adds instead is one bit, carried, and four lines that read it.

## The bit

| where | field | cost |
|---|---|---|
| x86 TLB entry | `TlbEntry::streaming` | 1 bit / TLB entry |
| `Request` | `STREAMING_BIT = 0x2000` in the **existing** `_cacheCoherenceFlags` bitfield | 0 — an unused encoding |
| `RubyRequest` | `m_isStreaming` | 1 bit |
| `CHIRequestMsg` | `isStreaming` | **1 bit on the wire** |
| CHI `TBE` | `isStreaming` | 1 bit / outstanding transaction |
| CHI `CacheEntry` | `isStreaming` | **1 bit / LLC tag** |

## The four lines

Everything else is plumbing. The decisions are these, verbatim from HEAD:

```slicc
// CHI-cache-funcs.sm, needCacheEntry()
((is_HN || enable_H3_streaming_bypass) && is_streaming) ||   // do not allocate

// CHI-cache-actions.sm, CheckCacheFill
bool need_fill := tbe.dataValid && (tbe.dataToBeInvalid == false)
                  && tbe.doCacheFill && !(is_HN && tbe.isStreaming);

// CHI-cache-actions.sm, H3 directory-enrolment skip
if (enable_H3_streaming_bypass && is_HN && tbe.isStreaming) { ... }
```

plus one extra parameter on `needCacheEntry`'s signature. Total
STREAMING-attributable added lines in gem5, non-comment and non-logging: **43**,
of which 4 are decision logic, 7 are flag propagation, 6 are field declarations,
and 26 are constructor/accessor plumbing for a single boolean.

## The clause the plan gets wrong: there is no new PTE bit

`PLAN_B_REBUILD.md` W6.1 says "unused PAT slot 6, **one PTE bit**, TLB carry,
one fill-path predicate." There is no new PTE bit. The decode reads the PAT
selector, PCD and PWT — three bits the page walker already reads on every walk —
and the whole of it is two lines per leaf size (`pagetable_walker.cc`):

```cpp
// PMD leaf: the PAT selector is bit 12
entry.streaming  = bits(pte, 12) && pte.pcd && !pte.pwt;
entry.uncacheable = uncacheable && !entry.streaming;
// 4K PTE: the PAT selector is bit 7
entry.streaming  = bits(pte, 7)  && pte.pcd && !pte.pwt;
entry.uncacheable = uncacheable && !entry.streaming;
```

The second line of each pair exists because slot 6 is WB-equivalent, so PCD must
not be honoured as "uncacheable" once the slot is claimed. **This is the paper's
title as an implementation fact**: the label is already in the translation, in
bits already being read, and costs four lines to notice. It is a stronger claim
than the plan makes and it should replace the plan's wording.

The new UAPI surface is **one line**: `PROT_STREAMING` in
`include/uapi/asm-generic/mman-common.h`. No new syscall.

**I0/I1 enforcement is six rejection rules**, all against VMA flags the kernel
already maintains (`streaming_validate_entry`): Xen PV, `VM_PAT`,
`VM_PFNMAP|VM_MIXEDMAP`, writable shared file-backed unless a sealed
single-mapper memfd, and userfaultfd-WP. It is a filter, not a new subsystem.

Against 447–564 lines of implementation there are 155 lines of KUnit, four
selftests totalling 662 lines, and a documentation file. **More test than
implementation** — worth saying, because "we added a memory type to Linux" reads
as expensive until the diff is on the page.

## What this audit does *not* establish

1. **Lines are not area, timing, or verification cost.** What the count bounds is
   *structural* complexity, and the structural numbers — zero new states, zero
   new message types, zero new structures, one wire bit, one tag bit — are the
   ones an architecture reviewer objects to. Report those as the claim and the
   line counts as context. Do not write "cheap" and cite a line count.
2. **H3's cost is not established, only H2's.** As realized in the model, H3 is
   variant (a) — no-retention, issued as `ReadOnce` (5,612,431 such transitions
   in the H3 arm and zero in every other, per W1.4) — and it is off by default
   (`enable_H3_streaming_bypass := "False"`). The sound retention variants (b)
   epoch-tagged-with-bulk-clear and (c) DeNovo self-invalidation are **unbuilt**,
   and their cost is an epoch-boundary drain that nothing here prices. Any cost
   sentence about H3 must say which variant it is costing.
3. **The kernel's exit drain is counted in lines, not cycles.** `WBNOINVD`
   broadcast to one CPU per core is 29 lines and an unknown number of
   microseconds. That is exactly the §3 δ embargo's unresolved flush overhead.
   Measuring the *streamer-side* cost of flush-behind is not embargoed and is the
   obvious follow-on; it would convert the largest remaining unpriced item into a
   number.
4. **`setstreaming` (pseudo-instruction 0x55) is a simulation artifact**, not
   proposed hardware. It exists because SE mode has no guest kernel to run
   `mprotect`. The FS path is the PAT decode above, and it has never been
   exercised end to end — that is W8.

## Two apparatus facts found while auditing, both worth recording

**1. The model's LLC is a victim cache, deliberately.** `CHI_config_8592.py`
sets, at the HNF: `alloc_on_readshared=False`, `alloc_on_readunique=False`,
`alloc_on_readonce=False`, `alloc_on_writeback=True`, commented "Non-inclusive
(victim cache): L2 evictions fill LLC, reads do not." This is correct Intel-NINE
modelling and it is load-bearing for how H2 works — H2's bypass acts on the
`WriteEvictFull` fill path, not on a read allocation. `tab:gem5cfg` should state
it. **Edit-queue candidate.**

**2. DMT defaults ON at the HNF, and only the finite-SF combination is guarded.**
`enable_DMT = env HNF_DMT, default 1`, and the config asserts only
`not (sf_finite and enable_DMT)`. An infinite-SF campaign that forgets
`HNF_DMT=0` would run with a different read pipeline than the finite-SF arms and
fail silently. **This did not happen**: `config.ini` was checked in all seven
surviving output directories (`sf_{qui,wb,h2}_inf_s1`, `sf_{wb,h2,h3}_fin_s1`,
`sf_h3_inf_s1`) and every one reads `enable_DMT=false`. `sf_inf_cells.sh` sets
it explicitly. Recorded because the guard does not cover the case that was
actually run, so the next person is protected by a launcher rather than by an
assert.

- Any cost sentence about H3 must name the variant it is costing (limit 2).

  types, or structures. Same finding, one day earlier.

  2026-08-23 memo makes the sharper version of this point than mine does: that
  word already carries `GLC`/`SLC` for shipped GPU bypass semantics, so the wire
