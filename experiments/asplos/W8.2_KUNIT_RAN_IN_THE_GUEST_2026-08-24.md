# W8.2 — the kernel's own streaming test suite ran, and passed, inside the simulated machine

Written 2026-08-24, from T4's boot console. **Zero compute cost:** this is
evidence T4 produced on the way to its checkpoint, not a run of its own.

## The finding

At guest t=4.82 s, before `/sbin/init`, the T4 boot ran the in-tree kunit suite
`pat_streaming` (module `streaming_kunit`) and reported:

```
    # Subtest: pat_streaming
    # module: streaming_kunit
    1..8
    ok 1 pat_streaming_msr_test
    ok 2 cachemode_table_roundtrip_test
    ok 3 pgprot_streaming_bits_test
    ok 4 pgprot_streaming_idempotent_test
    ok 5 large_encoding_test
    ok 6 vm_streaming_bit_test
    ok 7 arch_calc_streaming_bit_test
    ok 8 arch_validate_prot_test
# pat_streaming: pass:8 fail:0 skip:0 total:8
```

`skip:0` matters. Test 1 carries a `kunit_skip` for platforms whose PAT layout
is not the full-PAT one; it did not take it. The check therefore ran against
gem5's simulated CPU and passed.

W6 already counts these tests — "tests (kunit + 4 selftests) 830 lines" — as a
line item in the cost argument. **Nothing until now recorded that they had ever
been executed**, let alone executed inside the machine the paper simulates.

## What each test actually checks

Read from `linux/mm/streaming_kunit.c` rather than inferred from its names,
which is the W8.1 lesson.

| # | test | what it asserts |
|---|---|---|
| 1 | `pat_streaming_msr_test` | `rdmsrl(MSR_IA32_CR_PAT)` on the live CPU; slot 6 holds `PAT_WB_ENCODING` |
| 2 | `cachemode_table_roundtrip_test` | the cachemode↔protval tables invert each other |
| 3 | `pgprot_streaming_bits_test` | a streaming pgprot has PAT=1, PCD=1, PWT=0, PRESENT=1 |
| 4 | `pgprot_streaming_idempotent_test` | applying it twice equals applying it once |
| 5 | `large_encoding_test` | the PMD form uses `_PAGE_PAT_LARGE` not `_PAGE_PAT`, and `protval_large_2_4k` maps it back to the 4K form |
| 6 | `vm_streaming_bit_test` | `VM_STREAMING == 1UL << 36` |
| 7 | `arch_calc_streaming_bit_test` | `PROT_STREAMING` in, `VM_STREAMING` out; absent in, absent out |
| 8 | `arch_validate_prot_test` | `PROT_READ` accepted, `PROT_READ|PROT_STREAMING` accepted, unknown bit `0x40` still rejected |

Test 1 is the one with an external referent, and it says something the paper
should be precise about: **slot 6 encodes WB.** Streaming is not a new memory
type encoding — it is the *slot index* that carries the signal, and the byte in
that slot is ordinary write-back. On silicon that does not implement the
contract, a Streaming page is therefore exactly a WB page. That is the
safe-fallback property, and it is now demonstrated at the MSR level inside the
simulated machine rather than argued from the source.

## What this is worth, and what it is not

**Worth:** it is direct, machine-checked evidence for the OS half of L4 —
"OS-enforceable" — produced inside the simulated machine and entirely
independent of the benchmark, the declaration path, and every performance
number. If the benchmark's declaration were broken, these eight would still
pass; if these failed, no benchmark result would mean anything.

**Not:** it is not performance evidence and does not touch H1/H2/H3. It does not
show that `cxl_join_bench` declares correctly (that is T5's G2 gate). It does
not show a Streaming page behaves differently — only that the OS builds and
validates the encoding the contract specifies.

## The gap this exposes

The suite covers the **encoding** half of the OS contract. It does not cover the
**enforcement** half. Specifically, `mm/mprotect.c` rejects the combination:

```c
if (IS_ENABLED(CONFIG_PAT_STREAMING) &&
    (prot & PROT_STREAMING) && (prot & PROT_WRITE))
        return -EINVAL;
```

— the "must remain read-only for the lifetime of the region" rule, which is I1.
`arch_validate_prot_test` asserts that `PROT_READ|PROT_STREAMING` is *accepted*
and that an unknown bit is rejected; **it never asserts that
`PROT_STREAMING|PROT_WRITE` is refused.** That path is covered by the userspace
selftests — `tools/testing/selftests/mm/streaming_{reject,basic,hugetlb,memfd}.c`
— and T4 ran none of them: the busybox image runs the benchmark and nothing
else.

Stated as a limit rather than repaired. Adding the selftests to the guest image
is an apparatus change, the image is frozen for this campaign, and T5 does not
need them. It is a cheap and well-scoped addition to a *later* image, and the
immutability guarantee is the one part of I1 with no live evidence behind it.

## A trap in the console file

`system.pc.com_1.device` is **ISO-8859 with CRLF**, not UTF-8. Plain `grep`
classifies it as binary and prints *nothing* — not even "Binary file matches"
through a pipe — so a search for `streaming` in the boot console silently
returns empty and looks like an absent marker rather than an unreadable file.
Use `grep -a`. `t5_analyze.py` was already safe here (`console()` reads with
`errors="replace"`); its `stats.txt` reader was not, and has been hardened to
match, since gem5 has now been shown to emit non-UTF-8 into its output files.
