Written 2026-08-24. `W7_PREREGISTRATION_2026-08-23.md` §2 specifies Knob B as
"a software-pipelining change to `cxl_join_bench.cpp`'s fused loop only — same

Per F11's fifth fix, `experiments/asplos/` was listed for W7 first. Only the

## 1. What was built

`join_range_batched()` in `benchmarks/e2e/hash_join/src/cxl_join_bench.cpp`,
reached only via the new `--probe-batch k`. Default is 0, and at 0 or 1 the
binary takes the original `join_range` path — untouched, in the same convention
the file already uses for `join_range_local` and `join_range_hashed`.

Three stages per group of `k` tuples:

1. `k` independent hashes. `key[j] = fact[i+j].fk; pos[j] = hash64(key[j]) & mask;`
2. **`k` independent hash-table loads**, `ent[j] = table[pos[j]]`. This is the
   stage that raises memory-level parallelism and the only reason the function
   exists.
3. Consume. A collision that the already-loaded line does not resolve falls back
   to linear probing from `pos[j]+1`, reproducing `probe()` exactly.

Two implementation choices worth stating, because each could have silently
weakened the cell:

- **Real loads, not `_mm_prefetch`.** A prefetch is a hint a model may drop, and
  the object of the exercise is to put a known number of lines in flight. The
  loaded `Entry` also does double duty: the common case is resolved without a
  second access.
- **Stack arrays with `KMAX = 32`, not `std::vector`.** Lane state behind a heap
  pointer is state the compiler must reload. `k` is clamped to 32 — twice the
  modelled core's 16-entry L1d TBE budget, past anything worth testing.

`--result-hash` and `--no-stream` now **fail loudly** when combined with
`--probe-batch > 1` rather than silently ignoring one of the pair. Neither has a
batched twin, and a silently-ignored flag is how an arm gets mislabelled.

**The pre-W7 binaries were not overwritten.** W7 builds to
`build/cxl_join_bench_w7{,.gem5}` via a new `make w7` target. The Makefile now
records the pre-W7 hashes inline:

| binary | sha256 |
|---|---|
| `build/cxl_join_bench` | `3755f1c974e30034ee0618bae33a6a8e6baf718cd67b769139f271971d550786` |
| `build/cxl_join_bench.gem5` | `917413d5fab4e61404b89e905e3d09af91fed37afbe357483f297fc07194a069` |

Both verified unchanged after the build. F10 is precisely the inability to say
which binary produced a row, and a campaign that begins by overwriting the
previous campaign's binary starts inside that failure.

## 2. Correctness gate — 30 configurations, all pass

The pre-registration's gate is that `matches` is invariant across arms. Tested
across three shapes × ten values of `k`, native, `--policy wb`:

| fact | hot | morsel | seed | hit-rate | matches, every k ∈ {0,1,2,4,7,8,13,16,32,64} |
|---|---|---|---|---|---|
| 8 MiB | 2 MiB | 1 M | 1 | 0.5 | **260,531** |
| 7,999,984 B | 2 MiB | 999,983 | 7 | 0.3 | **149,174** |
| 5 MiB | 4 MiB | 333,331 | 12345 | 0.9 | **293,503** |
| 64 MiB | 512 MiB | 1 M | default | 0.5 | **2,088,306** |

Deliberately included: **odd `k`** (7, 13) and **morsel sizes that are not
multiples of `k`** (999,983 and 333,331 are prime), which exercise the serial
tail; and `k = 64`, which must clamp to 32 and does — its timings land on k=32's
within noise.

## 3. Choosing `k` — the native measurement, and why it is not P2

`active_cycles_per_access`, one thread, one rep. Two regimes:

| k | 2 MiB hot table (LLC-resident) | **512 MiB hot table (misses to DRAM)** |
|---:|---:|---:|
| 0 (serial) | 61.19 | **132.63** |
| 2 | 68.30 | — |
| 4 | 55.28 | 131.17 |
| 8 | 49.34 | **112.43** |
| 16 | 43.06 | **90.83** |
| 32 | 40.64 | **77.49** |

The 512 MiB column is the one that means anything for W7: mos181's LLC is 320
MiB, so a 512 MiB table misses for real and the loop is latency-bound. Batching
takes it from 132.6 to 77.5 cyc/access, **1.71×**, and to 90.8 at k=16
(**1.46×**). That is the memory-level-parallelism signature — the serial loop
waits, the batched loop overlaps.

Three things this measurement settles:

- **k = 2 is worse than serial** (68.3 vs 61.2 in the resident regime).
  Bookkeeping without enough parallelism to pay for it. The pre-registration's
  `k = 8` is above that floor; the knob should not be set below 4.
- **The gain saturates by k = 32** (k=64 clamps and does not improve). The
  pre-registration's target of "≥8 of the 16 L1d TBEs occupied" is reachable
  and is not at the edge of what the code can express.
- **Set `k = 16` for the campaign**, not 8. It sits mid-band, it is the modelled
  L1d TBE budget exactly, and native it delivers 1.46× where k=8 delivers 1.18×
  — enough headroom that a gem5 shortfall is informative rather than ambiguous.
  *This is a change to a pre-registered value and it is recorded as one*: the
  pre-registration says "`k = 8`, tunable," and this is the tuning, done before
  any A1 datum exists and justified by a native measurement that cannot see the
  outcome.

**None of this is P2.** P2 is "lines in flight ≥ 6" and "achieved fused
bandwidth ≥ 2.0 GB/s," both of which are gem5 counters against a CXL fact array
at 203 ns. mos181 native has no CXL, a 320 MiB LLC and a different core. What
the native run establishes is narrower and sufficient: the transformation is
correct, it does raise MLP when there are misses to overlap, and `k` is in the
right band. P2 is still open.

## 4. F12 — `--check` does nothing in `--mode morsel`

Found while looking for the correctness gate the pre-registration refers to.
`c.check` is read in exactly one place, `run_single` (line ~985), which computes
a `scalar_join` reference and compares. **`run_morsel` never reads it.** It
reports `matches_last_rep` and nothing validates it.

`run_gem5_fused_null.py:59-60` passes `--morsel 1m --check` to both the `wb` and
`h2` arms. That flag has been inert in every morsel run ever made. No published
number is wrong because of it — the real gate is cross-arm equality of
`matches_last_rep`, which a human performs and which does hold — but the runner
asserts a check that the binary does not perform, and anyone reading the runner
would believe the arms were self-validating.

**Not fixed, deliberately.** Making `--check` live in morsel mode would add a
full `scalar_join` pass over the fact array, which in gem5 is simulated cycles
before the measured region, and the apparatus rule is that apparatus is not
changed mid-campaign beyond the minimum required to run at all. W7's arms use
the cross-arm equality gate, stated explicitly rather than assumed from a flag.
Recorded in `W4.3_PROVENANCE_LEDGER_2026-08-23.md` as **F12**.
