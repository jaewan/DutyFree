# W4.4 — does any published number trace to the pre-D1/D2-fix binary?

**Verdict: no. But the audit that establishes this also falsifies the D1 write-up
and exposes a different, worse provenance defect.**

Run 2026-08-23 after applying `d1d2_pmu_and_l2size.patch` to mos181, the last
unpatched host. Method: keep the pre-fix binary, rebuild the post-fix one, and
compare them on the same host under the same sweep, rather than reasoning from
the constants.

## 1. What the AMD codes actually do on Intel

`RAW_L2_HIT=0x7064` / `RAW_L2_MISS=0x0864`, pre-fix source at `481115c`,
`victim -c 8 -w $w -d 2 -P`:

| host | part | ws 128 KB … 32 MB |
|---|---|---|
| mos181 | EMR Xeon 8592+ | `l2_hit=0 l2_miss=0` at **every** point |
| mos182 | SPR Xeon 8462Y+ | `l2_hit=0 l2_miss=0` at **every** point |

Cross-checked on mos181 with `perf stat -e r7064,r0864,r02d1,r10d1`: `r7064` and
`r0864` read exactly 0 while `r02d1`/`r10d1` track the working set correctly.
(perf's kernel tools are broken on mos182; the rebuilt pre-fix binary served
instead.)

So the README's "returned near-zero counts" is wrong in a way that matters: the
counters are **identically zero**, which is a signature, not noise. Any run that
used them is recognisable on sight.

## 2. Therefore the published Intel artifacts were not produced by that binary

`probe_mos182_matrix.jsonl` reports `l2_hit=684,240,681 / l2_miss=41,426` at
ws=1024 and `l2_hit=2,927 / l2_miss=138,779,053` at ws=16384 — a clean capacity
transition. The pre-fix binary cannot produce that. Three independent
confirmations that the producing binary had the *Intel* codes:

1. **Field presence.** The pre-fix `victim` stdout line ends at
   `iters=… sec=…`. It never prints `cyc_per_access`, `accesses`,
   `l2_counters`, `pmu`, or `ws_kb`. All 245 mos182 rows and all 423 moscxl
   rows carry `cyc_per_access` and `ws_kb`.
2. **Quantitative agreement.** Post-fix rebuild on mos182 vs the artifact, at
   working sets that match exactly:

   | ws | artifact `cyc_per_access` (3 reps) | post-fix rebuild |
   |---|---|---|
   | 1024 KB | 20.4255 / 20.4193 / 20.4383 | 20.4186 |
   | 2048 KB | 38.10 / 45.34 / 41.10 (at the knee) | 42.73 |
   | 4096 KB | 83.7468 / 83.6679 / 84.2989 | 83.9428 |

3. **Count scaling.** Artifact hit counts are 2.497× the rebuild's. `run_probe.py`
   uses `DUR=5`; the rebuild ran `-d 2`. 5/2 = 2.5.

`run_probe.py:154` also aborts the arm outright when `cyc_per_access` is absent,
so the pre-fix binary could not have completed a run even if it had been used.

## 3. mos181 never published an L2 number

The only `victim` invocation on mos181 in the whole tree is
`rocksdb/scripts/run_ptr_cat_ceiling.py`. Its artifact
(`ptr_cat_ceiling_mos181.jsonl`, 30 rows) records `ipc`, `llc_occupancy_end`
and CAT masks — **no L2 fields** — and it passes `-w` explicitly. D1 is
inapplicable (no L2 figure is read) and D2 is inapplicable (`victim.c:99` lets
`-w` override `DEFAULT_WS_KB`).

Every other runner also passes `-w` explicitly (`run_probe.py:128`,
`run_probe_moscxl.py:131`, `run_sfpressure.py:50`), so **D2 never bit anywhere.**

## 4. The defect this uncovered instead

The binary that produced the entire oltp_index campaign — 245 mos182 rows and
423 moscxl rows — was built from a source state that is **not in git**. It has
the Intel event codes and `cyc_per_access`, which `481115c` lacks; it lacks
`l2_counters`, `pmu`, and `accesses`, which the patched HEAD has. It is a third
state, and `tmp_dutyfree_exp` has only three commits and no stash on either
host. It cannot be reconstructed.

Same class as the uncommitted `tab:h3sf` launcher. Per §6.6 this is recorded as
gone, not reconciled. Practical consequence: **the numbers are sound but the
apparatus is not pinned.** Anything re-run from here uses the patched HEAD,
which is committed and self-reporting (`pmu=`, `l2_compiled=`, `l2_counters=`),
so the gap does not propagate forward.

## 5. mos181 post-fix verification (the patch README's prescribed check)

`pmu=intel`, `l2_compiled=2048 KB`, `l2_counters=ok`:

| ws_KB | 128 | 512 | 1024 | 1536 | 2048 | 4096 | 32768 |
|---|---|---|---|---|---|---|---|
| L2 miss % | 0.00 | 0.00 | 0.00 | 11.35 | 26.72 | 99.42 | 100.00 |
| cyc/access | 16.0 | 17.8 | 20.4 | 27.5 | 36.5 | 78.2 | 93.5 |

A capacity curve at the 2 MiB boundary, which a dead event code cannot produce.
All three hosts are now on the patched HEAD.
